## 本课目标

- 完整走一遍 Vibe Coding 全流程：**需求描述 → AI 生成 → 运行测试 → 迭代优化 → 展示**。

## 模块 1：Vibe Coding 全流程复盘（10 分钟）

### 知识点讲解

一个完整的 Vibe Coding 项目有 5 步，缺一不可：

1. **需求描述**：把"我想要什么"写成清单，越具体越好（功能、规则、界面、异常）。
2. **AI 生成**：用 Builder 一次生成，别急着提意见，先让它出完整版。
3. **运行测试**：亲手玩/用一遍，**专挑边角试**：输错会怎样？点快会怎样？
4. **迭代优化**：一次只提一个改进点，改完就测。
5. **展示**：能讲清楚"哪部分是我写的需求、哪部分是我提的修改"。

### 教师演示脚本

拿贪吃蛇参考项目快速演示第 3、4 步：故意撞墙、撞自己，展示游戏结束逻辑；然后发一条提示词「把蛇的移动速度加快一点」现场迭代。

## 模块 2：三个自选项目与提示词模板（15 分钟）

> 用法：**先自己写需求（三次提示法），写不出来再参考模板；模板也要改成自己的话再发。**

### 项目 A：待办清单（难度 ★，适合求稳的同学）

功能：添加待办、勾选完成、删除、显示剩余数量、数据刷新后还在（localStorage）。

> **提示词模板**：
>
> ```
> 帮我做一个网页待办清单（index.html 单文件，CSS/JS 内嵌），要求：
> 1. 顶部有输入框和"添加"按钮，输入文字点添加后出现在列表里；
> 2. 每条待办左边是勾选框，勾选后文字加删除线并变灰；右边有"删除"按钮；
> 3. 底部显示"还剩 X 件事未完成"；
> 4. 用 localStorage 保存数据，刷新页面后待办不丢失；
> 5. 界面美观：卡片式布局、圆角、hover 效果，配色清新；
> 6. 代码加中文注释。
> ```

### 项目 B：贪吃蛇（难度 ★★，有参考源码）

功能：方向键控制蛇移动、吃食物变长加分、撞墙或撞自己结束、可重新开始。

> **提示词模板**：
>
> ```
> 帮我做一个网页贪吃蛇游戏（index.html 单文件，CSS/JS 内嵌），要求：
> 1. 用 canvas 画 20×20 的网格地图，蛇是绿色方块，食物是红色方块；
> 2. 方向键控制蛇移动，蛇每 150 毫秒前进一格；
> 3. 吃到食物蛇身加 1 节、加 10 分，食物随机出现在新位置（不能出现在蛇身上）；
> 4. 撞墙或撞到自己游戏结束，显示总分和"按空格重新开始"提示；
> 5. 页面顶部实时显示分数；
> 6. 代码加详细中文注释。
> ```

### 项目 C：数字华容道（难度 ★★★，适合挑战者）

功能：4×4 方格乱序排列 1~15，点击空格旁边的数字滑入空格，全部排好则胜利，显示步数和用时。

> **提示词模板**：
>
> ```
> 帮我做一个网页数字华容道（index.html 单文件，CSS/JS 内嵌），要求：
> 1. 4×4 网格，格子显示数字 1~15，留一个空格；
> 2. 开局随机打乱（保证有解：打乱可以用"从排好的状态随机滑动 200 步"的方式）；
> 3. 点击空格相邻的数字块，该块滑入空格；
> 4. 页面显示已用步数和计时（秒）；
> 5. 当数字按 1~15 顺序排好时，弹出"恭喜通关！用了 X 步 Y 秒"，并提供"再来一局"按钮；
> 6. 方块有圆角和数字居中，点击有动画过渡；
> 7. 代码加详细中文注释。
> ```

### 学生动手任务（10 分钟）

选定项目，按三次提示法写出**第一版需求**并发给 Builder。要求需求里至少包含：3 条功能、1 条界面要求、1 条异常情况说明（例如"输入为空时不添加"）。

## 模块 3：迭代优化冲刺（30 分钟）

### 教师巡回指导要点

- 学生卡住时，先问"你的提示词是什么？"——80% 的问题是需求没说清。
- 报错处理流程：复制报错 → 贴给 Chat → 加一句"我是初学者"。
- 提醒保存：每次 AI 改完先 Ctrl+S 再刷新浏览器。

### 迭代清单（每人至少完成 2 项）

- [ ] 改一处外观（配色 / 圆角 / 字体），**手动改代码**完成（不用 AI，练习读懂代码）。
- [ ] 加一个新功能（用提示词让 AI 加），例如：最高分记录、音效、难度选择。
- [ ] 故意制造一个边界情况测试（输入为空、快速连点、乱按方向键），有问题就让 AI 修。

> **AI 提示词示例**（迭代时万能句式）：
>
> ```
> 这是我现在的代码（粘贴），运行正常。我想加【一个具体功能】，要求【具体规则】。请只修改必要的部分，并告诉我改了哪几个地方、为什么。
> ```

## 模块 4：结课展示（30 分钟）

每人 2 分钟，讲三件事：

1. **演示**：现场玩/用一遍你的项目。
2. **分工**：哪部分是你写的需求？AI 第一版哪里不满意？你提了什么修改？
3. **收获**：这 8 节课你觉得最酷的一个瞬间是什么？

### 评分参考（老师用）

| 维度 | 分值 | 说明 |
| --- | --- | --- |
| 项目能完整运行 | 40 | 无致命 bug，核心功能可用 |
| 需求表达能力 | 30 | 能讲清自己的提示词和迭代过程 |
| 代码理解 | 20 | 能指出代码里至少 2 处"这是干什么的" |
| 创意与美观 | 10 | 有自己的想法 |

## 课后挑战（结课后自选）

- 把作品部署到网上让家人访问（问 AI：「怎么把我的 HTML 网页免费部署到 GitHub Pages」）。

## 常见问题与 AI 排错指南

| 现象 | 应对 |
| --- | --- |
| AI 生成的代码一次跑不起来 | 正常！把报错原样贴回 Builder：「运行报这个错：xxx，请修复」 |
| 改了一个功能，另一个功能坏了 | 让 AI「检查最近的修改是否影响了其他功能」，必要时回退 |
| localStorage 数据混乱 | 问 Chat 如何清空：「浏览器怎么清空某个网站的 localStorage」 |
| 完全不知道 bug 在哪 | 分段排查：用 `console.log` 在关键位置打印，缩小范围后贴给 AI |

**结课寄语**：8 节课你学会的不是"背语法"，而是 AI 时代最重要的能力——**把想法说清楚、把结果验证好**。以后做任何项目，都记得今天这五步。
