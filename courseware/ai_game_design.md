# 专题章：AI 协同游戏设计 · 外星人入侵

> 面向 12 岁以上零基础学生；建议 4～6 课时。最终作品：可用键盘操作、会计分、会升级、可重新开始的 Pygame 射击游戏。
>
> 配套代码：`projects/alien_invasion_ai/`；课堂工作台：网站 `/game-lab`。本专题是独立扩展章，不属于原课程的第 1～8 课。

## 一、章节定位与学习成果

这不是一次「让 AI 把游戏全做完」的演示，而是一条 **人提出问题、人读懂代码、人动手修改、人负责验收** 的完整学习路径。每一步都有独立可运行的 `main.py`，某一步没有完成，也能进入下一步继续学习。

完成本专题后，学生应能：

- 在真实项目中辨认并使用变量与数值、布尔值、`if`、`while`、`for`、函数、列表、类与对象。
- 说明模块拆分的好处，选讲字典和参数配置。
- 分别使用 Trae IDE 模式与 Trae SOLO 模式协作，并说出两种模式的不同分工。
- 不直接接受 AI 的答案，而是通过运行、边界测试、连续射击、碰撞、失败与重开来验收。
- 至少亲手完成 8 次小修改，并完成一种个性化改造。

### 最终操作键

| 按键 | 功能 |
| --- | --- |
| `←` / `→` | 左右移动飞船 |
| `空格` | 发射子弹 |
| `Enter` | 游戏结束后重新开始 |
| `Q` / `Esc` | 退出游戏 |
| 窗口右上角 `×` | 退出游戏 |

### 3. 运行任一步骤

```bash
cd projects/alien_invasion_ai/steps/step01
```

最终模块化版本：

请在本机的 Trae 中运行 Pygame。课程网页是学习和记录进度的工作台，**不会在网页里直接运行 Pygame 游戏**。

- 每步先运行原版，再一次只改一个参数，改后立即运行。

## 三、IDE 与 SOLO：两种 AI 协作方式怎么分工

| 维度 | Trae IDE 模式 | Trae SOLO 模式 |
| --- | --- | --- |
| 节奏 | 教师/学生控制，一次改一小处 | 学生描述完整目标，AI 规划并执行 |
| 主要动作 | 写中文注释、代码补全、Chat 小步问答 | 自然语言需求、自动修改、运行、迭代 |
| 学生重点 | 读懂每一行，预测修改结果 | 写清上下文、约束和验收条件 |
| 适合场景 | 学语法、调参数、定位小错误 | 搭完整原型、组合多个已有功能 |
| 必须守住 | 不整段盲贴；能解释关键代码 | 不以「AI 说完成」代替实际测试 |
| 本专题用法 | 每步先手动改「学生修改区」 | 用本步 SOLO 提示词复现或扩展，再按清单验收 |

### 推荐课堂节奏

1. **人手先行**：学生先改一个数字或颜色，并预测效果。
2. **IDE 追问**：选中一段代码，问「逐行解释，不要改代码」。
3. **SOLO 对照**：让 SOLO 在副本中完成同一目标，比较修改范围。
4. **统一验收**：无论谁写的代码，都通过同一组检查点。

### SOLO 提示词通用结构

> **上下文**：当前是哪一步、哪个文件、已经有什么功能。
> **目标**：这一步只新增什么。
> **约束**：单文件、中文注释、Pygame 图形、保留操作键等。
> **运行验证**：要求实际运行并检查什么。
> **保护条件**：不得破坏已有功能，不做无关重构，不删除学生修改区。

## 四、8 步详细教学流程

每一步都按「语法讲解 → 教师演示 → 可复制提示词 → 学生亲手改代码 → 检查点 → 常见报错」进行。提示词中的路径可按实际打开目录调整。

### 第 1 步：游戏窗口与主循环

**对应代码**：`steps/step01/main.py`

#### 本步目标与语法

- 创建窗口，认识「初始化 → 主循环 → 绘制 → 退出」。
- 变量保存窗口宽度、高度、颜色和标题；数值可以进行计算。
- `while running:` 让程序持续工作；`for event in pygame.event.get():` 逐个处理事件。
- `if` 判断退出事件；布尔值 `running = False` 结束主循环。

#### 教师演示

先让学生预测 `SCREEN_WIDTH = 900` 改成 `960` 后会发生什么，再修改运行。指出：如果主循环里不处理事件，窗口会像「卡死」一样；`clock.tick(60)` 限制每秒最多约 60 帧。

**IDE 模式提示词（复制到 Chat）**：

```text
我是 Python 零基础学生，正在学习 Pygame。请打开 steps/step01/main.py，只逐行解释窗口变量、while 主循环、事件退出和 clock.tick(60)，不要修改代码。然后给我一个只改窗口背景色的小练习，并告诉我应该改哪一行。
```

**SOLO 模式提示词**：

```text
上下文：这是 AI 协同游戏设计专题的第 1 步，当前只有 steps/step01/main.py，使用 Pygame 绘制窗口，无外部素材。
目标：制作一个 900×600 的游戏窗口，标题为「AI 外星人入侵 · 第1步」，背景为深蓝色，并能稳定刷新。
约束：保持单文件 main.py 和中文注释；保留「学生修改区」；点击关闭按钮、按 Q 或 Esc 都能退出；不要添加飞船、子弹等后续功能，不依赖网络或图片。
运行验证：请实际启动程序，确认窗口可显示和退出；检查没有语法错误。
保护条件：不得破坏已有事件循环和 60 FPS 限速，不做无关重构。完成后列出修改点和手动验收方法。
```

#### 学生亲手改代码

在「学生修改区」把窗口改为 `960×640`，背景色改为 `(240, 248, 255)`，标题加上自己的姓名或昵称。

#### 完成检查点

- [ ] 窗口尺寸、背景色和标题确实发生变化。
- [ ] 窗口能持续显示，不会立即退出。
- [ ] 关闭按钮、`Q`、`Esc` 都能退出。
- [ ] 能指出一个变量、一个 `while` 和一个 `if`。

#### 常见报错

| 现象/报错 | 排查 |
| --- | --- |
| `ModuleNotFoundError: No module named 'pygame'` | 在当前 Python 环境执行 `python -m pip install pygame`。 |
| 窗口无响应 | 检查 `pygame.event.get()` 是否仍在主循环中。 |
| `IndentationError` | 检查 `while`、`for`、`if` 内代码是否统一缩进 4 个空格。 |

### 第 2 步：飞船与左右移动

**对应代码**：`steps/step02/main.py`

#### 本步目标与语法

- 用 `Ship` 类描述飞船的数据和行为，用 `ship = Ship(...)` 创建对象。
- `self.x` 保存浮点精确位置，`self.rect.centerx` 负责绘制位置。
- `moving_left`、`moving_right` 是布尔标志；按键按下设为 `True`，松开设为 `False`。
- 用 `if` 和左右边界限制，避免飞船飞出屏幕。

#### 教师演示

先只按一下方向键，观察飞船持续移动；松开后停止。追问「为什么不能只在 KEYDOWN 时移动一次？」再演示把 `self.x` 同步到 `rect`，说明浮点速度不会被每帧取整吞掉。

**IDE 模式提示词**：

```text
请阅读 steps/step02/main.py 中的 Ship 类。用初学者能懂的话解释 self.x、self.rect、moving_left 和 moving_right 的关系，不要改代码。然后请用注释 + 代码补全引导我把飞船速度从 4.0 改为 6.0，一次只给一步。
```

**SOLO 模式提示词**：

```text

目标：在窗口底部中央创建三角形飞船，按住左右方向键连续移动，松开停止，并始终留在屏幕内。
约束：使用 Ship 类和对象、布尔移动标志、if 边界判断；self.x 用浮点数保存位置；保持单文件和中文注释；保留第 1 步窗口、60 FPS 以及 Q/Esc/关闭按钮退出。
```

#### 完成检查点

- [ ] 长按左右键能连续移动，松开立即停止。

#### 常见报错

| 现象/报错 | 排查 |
| --- | --- |
| 按键只动一下 | 检查是否使用持续更新的移动标志，而非只在 KEYDOWN 改坐标。 |
| 松键后仍移动 | 检查 `KEYUP` 是否把对应标志设回 `False`。 |

### 第 3 步：发射子弹

**对应代码**：`steps/step03/main.py`

#### 本步目标与语法

- 用 `fire_bullet()` 函数封装发射动作。
- 用列表 `bullets` 保存多个子弹对象；`for bullet in bullets[:]` 遍历列表副本。
- 空格键触发发射；同屏数量不超过 `BULLETS_ALLOWED`。
- 子弹飞出顶部后删除，避免列表越来越长。

#### 教师演示

**IDE 模式提示词**：


**SOLO 模式提示词**：

把子弹颜色改为橙色，把 `BULLET_SPEED` 改为 `9.0`，把 `BULLETS_ALLOWED` 改为 `6`，观察射速与同屏数量的区别。

- [ ] 空格能从飞船当前位置发射子弹。

| 现象/报错 | 排查 |
| --- | --- |

### 第 6 步：子弹与外星人碰撞

**对应代码**：`steps/step06/main.py`

#### 本步目标与语法

- 用 `bullet.rect.colliderect(alien.rect)` 检测两个矩形是否重叠。
- 在遍历副本时安全删除子弹和外星人；命中后 `break` 内层循环。
- 每命中一个外星人增加分数；舰队清空后重新生成。

## 五、AI 生成后怎么验收

「代码看起来完整」不等于「游戏正确」。每组至少由一名学生操作、一名学生记录。

- [ ] **运行**：从干净终端启动，没有语法错误、导入错误或资源路径错误。
- [ ] **测试边界**：飞船长按左右键到边缘，不越界；舰队碰边只转向一次。
- [ ] **连续射击**：移动中连续按空格，不突破同屏上限，离屏子弹会删除。
- [ ] **碰撞**：一次命中只加一次分；子弹与外星人按规则消失；清空后能重建。
- [ ] **失败/重开**：撞船与到底均扣命；生命耗尽后停止更新；Enter 后状态正确恢复。
- [ ] **代码阅读**：能解释本步至少 3 行关键代码，并指出自己亲手修改的位置。
- [ ] **回归**：新功能没有破坏移动、退出、计分等旧功能。

> 向 AI 反馈失败时，不要只说「不行」。使用：「我执行了___，预期___，实际___，完整报错是___。请只修复这个问题，并保留已有功能。」

## 七、扩展挑战

按从易到难选择，仍坚持「一次一项 + 写完就测」。

1. **速度上限**：为外星人速度设置最大值，避免高关卡完全无法游玩。
2. **关卡奖励**：每清空一支舰队额外加 `level × 50` 分，并核对计分。
3. **难度字典**：用字典保存简单/普通/困难的速度和生命参数，开局选择一种。
4. **持久最高分**：把最高分写入本地 JSON 文件；处理文件不存在和内容损坏的情况。
5. **暂停功能**：按 `P` 切换布尔状态，暂停时继续响应退出和恢复事件。
6. **新阵型**：用嵌套循环生成三角形或交错舰队，不手工复制对象。
7. **声音设计**：仅在教师提供本地素材或学生自行录制后添加音效，不引入网络依赖。
8. **自动化冒烟测试**：学习用 dummy 视频驱动和自动退出事件检查游戏能否启动。

## 八、教师使用建议

- **零基础班**：每步用「运行原版 → 改一个参数 → 解释一行 → 勾选检查点」即可，SOLO 作为对照演示。
- **进阶班**：要求先写 SOLO 验收条件，再让 AI 执行；重点评价测试记录而非生成速度。
- **掉队学生**：直接打开下一步的独立 `main.py`，不用回头修复上一步才能继续。
- **防包办**：随机抽问关键行；修改任务必须先由学生完成，再允许 AI 优化。
- **课堂收尾**：使用 `student_worksheet.md` 收集每一步的修改、测试和分工证据。
